Expand description

A zarr v3 save store, or one of its subgroups; ext/SAVE-FORMAT.md specifies the layout.

Shard-tier arrays are created on first write, so a subgroup holds only the kinds it uses. Their payloads are too small for zstd to pay, unlike the stream tier’s quasi-inverses.

Fields§

§path: PathBuf

Filesystem root of the underlying store, shared by all subgroups.

§store: ReadableWritableListableStorage

Underlying zarr storage, shared by all subgroups.

§group: String

Group prefix of every operation: empty for the root store, e.g. /products/foo otherwise.

§created: DashSet<SaveKind>

Shard-tier arrays known to exist, so later writes skip the metadata check.

§arrays: DashMap<SaveKind, Arc<Array<dyn ReadableWritableListableStorageTraits>>>

Opened shard-tier arrays, so each kind’s zarr.json is parsed once.

An Array holds no chunk data and its methods take &self, so one handle serves concurrent reads and shard-serialized writes.

§locks: Arc<GroupLocks>

The locks of this group, shared by every handle on it; see GroupLocks.

pub fn create(path: impl AsRef<Path>) -> Result<Self>

Open the store at path, creating its root group if absent.

An existing store is opened as is; Self::bind_to_algebra and Self::bind_module_spec check that it holds the expected complex. Fails if the path cannot be resolved or the store cannot be opened or initialized.

Source

pub fn bind_to_algebra( &self, algebra_magic: u32, prime: u32, algebra_prefix: &str, ) -> Result<()>

Bind this store to the algebra algebra_magic, recording it with prime and the prefix.

A store bound to another algebra is an error. Self::bind_module_spec pins the module, and construct_from_save reads algebra_prefix back. Subgroups share these attributes.

Source

pub fn set_complex_name(&self, name: &str) -> Result<()>

Record name as the root group’s complex_name, a label that never gates loading.

Source

pub fn bind_module_spec(&self, spec: &Value) -> Result<()>

Bind this store to the module spec, recording it in the root group.

A store bound to a different module over the same algebra is an error. The recorded spec is what construct_from_save rebuilds the complex from.

Source

pub fn bind_resolver(&self, resolver: &str) -> Result<()>

Bind this store to the algorithm that resolves the complex, e.g. "nassau".

Algorithms choose different generators and differentials, so data built on one resolution, such as secondary homotopies, is wrong for another resolution of the same complex. A store bound to another algorithm is an error.

The shard-tier array for kind, created if absent and grown to cover zarr_coords.

zarrs stores an element outside an array’s shape without complaint, but a reader that follows the zarr spec cannot see it, so the shape must grow first. Each axis that is too short at least doubles, which keeps every axis a multiple of its shard length.
